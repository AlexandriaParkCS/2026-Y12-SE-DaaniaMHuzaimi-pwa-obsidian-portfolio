**Project:** SleepTracker PWA
**Module:** Application factory, SQLAlchemy models

**What I did:**
- Created the Flask application factory (`create_app()`) in `app.py` using the factory pattern, registering `auth_bp` and `sleep_bp` blueprints.
- Created `database.py` with a shared `db = SQLAlchemy()` instance to avoid circular imports between `app.py` and the model files.
- Implemented `models/user.py` with the `User` class: `id`, `username`, `password_hash` columns; `set_password()` using `bcrypt.generate_password_hash()`; `check_password()` using `bcrypt.check_password_hash()`; and a `sleep_entries` relationship with `cascade='all, delete-orphan'`.
- Implemented `models/sleep_entry.py` with the `SleepEntry` class: `id`, `user_id` (FK), `bedtime`, `wake_time`, `quality`, `notes` columns; `calculate_duration()` method computing hours from `wake_time - bedtime`; `quality_label` and `quality_colour` properties.
- Implemented `models/sleep_goal.py` with `SleepGoal`: `id`, `user_id` (FK), `target_hours`.
- Created `models/__init__.py` importing `User`, `SleepEntry`, `SleepGoal`.
- Set up the SQLite database at `runtime/db/sleep.db` using `db.create_all()` inside the app context.

**Why I did it:**
- The factory pattern (`create_app()`) is used instead of a module-level `app = Flask(__name__)` because it prevents circular imports and makes the app easier to configure for different environments (development vs. production).
- `database.py` as a separate file means both `app.py` and the model files can safely `from database import db` without creating an import cycle.
- `cascade='all, delete-orphan'` on the `sleep_entries` relationship ensures that when a user deletes their account, all their sleep data is automatically removed as its important for privacy compliance.
- bcrypt was chosen over MD5 or SHA for password hashing because it generates a unique salt per hash and is computationally slow by design, making brute-force attacks impractical.

**Challenges:**
- Initially placed `db = SQLAlchemy(app)` inside `app.py`, which caused a circular import when `models/user.py` tried to import `db`. Resolved by creating the separate `database.py` pattern.
- `db.create_all()` must be called inside `with app.app_context():` calling it outside the context raises a `RuntimeError: No application found`. Fixed by wrapping it correctly in the factory function.
