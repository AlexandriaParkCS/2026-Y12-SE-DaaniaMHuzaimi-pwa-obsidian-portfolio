**Date:** 14 May 2026
**Project:** SleepTracker PWA
**Module:** ZenQuotes API integration and dashboard completion

**What I did:**
- Extracted a `get_quote()` helper function in `routes/sleep.py`:
  ```python
  def get_quote():
      try:
          response = requests.get('https://zenquotes.io/api/today', timeout=5)
          data = response.json()
          return data[0]['q'], data[0]['a']
      except Exception:
          return "Sleep is the best meditation.", "Dalai Lama"
  ```
- Called `get_quote()` in the dashboard route and passed `quote` and `author` to `dashboard.html`.
- Used Bootstrap `col-6 col-md-4` grid for stat cards so they display 2-per-row on mobile and 3-per-row on tablet+.

**Why I did it:**
- `timeout=5` in the `requests.get()` call prevents the dashboard from hanging indefinitely if ZenQuotes is slow or unreachable. Without a timeout, a network issue would block the entire Flask response thread.
- `except Exception` (broad catch) is intentional here  it catches network errors (`ConnectionError`), JSON parse errors (`JSONDecodeError`), and index errors (`IndexError`) all in one, ensuring the page always renders with a fallback quote rather than a 500 error.

**Challenges:**
- ZenQuotes returns a list: `[{"q": "...", "a": "..."}]`. Initially accessed `data['q']` expecting a dict, which raised `TypeError: list indices must be integers or slices, not str`. Fixed by using `data[0]['q']`.

**Extra notes:**
The `try/except` pattern for API calls is something I'll use in every project from now on. An external API is outside your control it can go down, change its response format, or time out. Defensive coding with a fallback means your own app never breaks because of someone else's service.
