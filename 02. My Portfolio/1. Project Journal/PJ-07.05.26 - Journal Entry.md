**Date:** 7 May 2026
**Project:** SleepTracker PWA
**Module:** Sleep CRUD routes and all remaining templates

**What I did:**
- Built `routes/sleep.py` as a `Blueprint('sleep', __name__)` with the following routes, all decorated with `@login_required`:
  - `GET/POST /dashboard`: queries last 7 `SleepEntry` records for `session['user_id']`, calculates average duration and average quality, fetches wellness quote via `get_quote()`, passes data to `dashboard.html`.
  - `GET/POST /log`: renders `SleepEntryForm`, on valid POST sanitises `notes` field with `sanitise()`, saves new `SleepEntry` to DB.
  - `GET/POST /edit/<int:entry_id>`: queries `SleepEntry.query.filter_by(id=entry_id, user_id=session['user_id']).first_or_404()` IDOR protection; on valid POST updates and commits.
  - `POST /delete/<int:entry_id>`: same IDOR-protected query, then `db.session.delete(entry)`.
  - `GET /history`: queries all `SleepEntry` records for current user, ordered by `bedtime.desc()`.
  - `GET/POST /goal`: queries or creates `SleepGoal` for current user.
  - `GET /privacy`: renders static `privacy.html`.
- Built all remaining templates: `dashboard.html` (quote), `log_sleep.html`, `edit_sleep.html`, `history.html`, `goal.html` (with danger zone delete form), `privacy.html` (5 sections).
- Fixed `history.html` structural bug: Edit `<a>` button was inside the delete `<form>` tag. Moved it before the `<form>` opening tag.
- Fixed `privacy.html`: `{% endblock %}` was nested inside closing `</div>` tags. Moved to after all closing divs.

**Why I did it:**
- To protect against IDOR attacks, the edit and delete queries check both the `entry_id` and the logged-in user’s ID. Without the `user_id` check, one user could change the URL and access another user’s entries.
- `first_or_404()` is used instead of `first()` because `first()` returns `None` when no result is found, which can later cause errors in the code. `first_or_404()` automatically shows a proper 404 error page instead.
- Notes are cleaned using `sanitise()` before being saved to stop stored XSS attacks. Without this, someone could save harmful script code in a note that would run in other users’ browsers when the page loads.

**Challenges:**
- The Edit button inside the delete `<form>` was visually undetectable it looked correct in the browser. Only careful reading of the HTML source revealed it. HTML does not allow nested `<form>` elements; the edit `<a>` was being absorbed into the delete form, meaning clicking "Edit" would submit the delete form.
- `{% endblock %}` inside the `</div>` structure in `privacy.html` caused Jinja2 to silently produce malformed HTML where the `</div>` tags were outside the `{% block content %}` scope, breaking the page layout on all inherited themes.
