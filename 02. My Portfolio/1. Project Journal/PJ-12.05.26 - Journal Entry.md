**Date:** 12 May 2026
**Project:** SleepTracker PWA
**Module:** PWA manifest.json, serviceWorker.js, app.js

**What I did:**
- Created `static/manifest.json` with: `name`, `short_name`, `start_url: "/"`, `display: "standalone"`, `background_color`, `theme_color`, `icons` array referencing `icon-192x192.png` and `icon-512x512.png`.
- Created `static/js/serviceWorker.js` with:
  - `CACHE = 'sleeptracker-v1'`
  - `ASSETS` array with absolute paths: `"/"`, `"/static/css/bootstrap.min.css"`, `"/static/css/style.css"`, `"/static/js/bootstrap.bundle.min.js"`, `"/static/js/app.js"`, `"/static/manifest.json"`, `"/static/icons/icon-192x192.png"`, `"/static/icons/icon-512x512.png"`
  - `install` event: `cache.addAll(ASSETS)`
  - `activate` event: `keys.filter(key => key !== CACHE).map(key => caches.delete(key))` deletes old caches
  - `fetch` event: cache-first strategy with network fallback
- Created `static/js/app.js` with:
  - Service worker registration: `navigator.serviceWorker.register('/static/js/serviceWorker.js')`
  - Theme toggle logic: reads `localStorage.getItem('theme')` on load, sets `document.documentElement.setAttribute('data-theme', theme)`, cycles dark -> light -> purple ->dark on button click, saves to `localStorage.setItem('theme', theme)`

**Why I did it:**
- All asset paths in `ASSETS` start with `/` (absolute paths) rather than relative paths like `static/css/style.css`. Relative paths are resolved relative to the service worker's own location (`/static/js/`), which would produce `/static/js/static/css/style.css` a path that doesn't exist, causing the install to fail silently.
- The `activate` event uses `key !== CACHE` (not `===`) to filter old caches for deletion. `!==` means "delete every cache that is NOT the current version" using `===` by mistake would delete the current cache and keep all old ones, which is the exact opposite of the intended behaviour.
- `localStorage` is used for theme persistence instead of Flask session because the theme toggle must work client-side without a server request, and must function offline when the app is served from the service worker cache.
- `navigator.serviceWorker.register('/static/js/serviceWorker.js')` uses an absolute path starting with `/`. Without the leading slash, on any URL other than the root the path is resolved as relative (e.g. `/dashboard/static/js/serviceWorker.js`), which returns a 404.

**Challenges:**
- The `===` vs `!==` bug in the activate handler caused the app to always load the old cached version after updates the current cache was being deleted while stale caches were preserved. Only noticed when changes weren't appearing after a hard reload.
- Service worker registration initially used `"static/js/serviceWorker.js"` (no leading slash). This worked on the `/` route but failed silently on every other route. Verified in Chrome DevTools -> Application ->Service Workers and saw the registration error.
- Service workers only update when all tabs with the app are closed and reopened. This made testing updates confusing had to use "Update on reload" in DevTools during development.
