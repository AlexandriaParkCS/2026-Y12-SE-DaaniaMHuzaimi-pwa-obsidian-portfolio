**Why I did it:**
- IDOR simulation (TC-013) was done by logging in as two separate accounts, noting an entry ID belonging to Account B, then attempting `/edit/<B's entry id>` while logged in as Account A. The expected result is a 404 confirming the `filter_by(id=entry_id, user_id=session['user_id'])` protection works.
- W3C validation is required by the rubric (criteria 3.5) and ensures the HTML is syntactically correct. Errors like stray `</div>` tags can cause inconsistent rendering across browsers.

**Challenges:**

(2) The delete confirmation dialog text referred to the wrong field name a copy-paste error in the template, fixed in one line.
- W3C validator requires pasting the *rendered* HTML (not the Jinja2 source). Used Chrome -> View Page Source -> copy -> paste into validator.
