**Date:** 30 Apr 2026
**Project:** SleepTracker PWA
**Module:** WTForms, auth routes, security features

**What I did:**
- Built `forms.py` with four WTForms classes: `RegistrationForm` (username, password, confirm_password with `EqualTo` validator), `LoginForm` (username, password), `SleepEntryForm` (bedtime, wake_time as `DateTimeLocalField`, quality as `SelectField` 1–5, notes as `TextAreaField`), and `SleepGoalForm` (target_hours as `FloatField`).
- Added a custom `validate_wake_time()` method on `SleepEntryForm` to raise `ValidationError` if `wake_time <= bedtime`.
- Built `routes/auth.py` with a `Blueprint('auth', __name__)` containing:
  - `/register` (GET/POST): sanitises username with `sanitise()`, checks for duplicate username, calls `user.set_password()`, commits to DB, redirects to login.
  - `/login` (GET/POST): queries user by username, calls `check_password()`, calls `session.clear()` before setting `session['user_id']`, shows generic error "Invalid username or password" regardless of which field was wrong.
  - `/logout`: calls `session.clear()`, redirects to login.
  - `/delete_account` (POST): fetches user by `session['user_id']`, calls `db.session.delete(user)`, commits, clears session.
- Implemented `login_required` decorator using `@wraps(f)` from `functools`.
- Implemented `sanitise(text)` using `re.sub(r'<[^>]+>', '', text)` to strip HTML tags.

**Why I did it:**
-  I used WTForms instead of manually handling POST data because it already includes validation, CSRF protection, and makes forms easier to manage when errors happen. This reduces the chance of missing validation issues.
- Using `session.clear()` before setting `session['user_id']` helps stop session fixation attacks, where someone could force a user to use a known session ID before logging in.
- Showing a generic login error message like “Invalid username or password” improves security because it stops attackers from figuring out which usernames exist in the database.
- `@wraps(f)` is needed in the `login_required` decorator because without it, Flask thinks all decorated routes have the same function name, which causes routing errors.

**Challenges:**
- Initially forgot `@wraps(f)` on the `login_required` decorator. Flask raised `AssertionError: View function mapping is overwriting an existing endpoint function: decorated`. Adding `from functools import wraps` and `@wraps(f)` resolved it.
- The custom `validate_wake_time` validator on `SleepEntryForm` must be named exactly `validate_<fieldname>` for WTForms to detect and run it automatically. Initially named it `check_wake_time` and it silently never ran.
