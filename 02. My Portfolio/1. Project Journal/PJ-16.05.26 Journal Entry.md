**Date:** 16 May 2026
**Project:** SleepTracker PWA
**Module:** Privacy page, accessibility, CSS polish

**What I did:**
- Completed `privacy.html` with 5 sections: (1) What data we collect, (2) Why we collect it, (3) How it is protected, (4) Your rights (with link to delete account), (5) Contact/acknowledgement.
- Fixed `{% endblock %}` placement it had been inside the closing `</div>` structure. Moved to the final line of the file, after all `</div>` tags close.
- Added accessibility features across all templates:
  - Skip link in `base.html`: `<a href="#main-content" class="skip-link">Skip to content</a>`
  - `role="main"` on `<main id="main-content">` 
  - `role="navigation"` on `<nav>`
  - `role="contentinfo"` on `<footer>`
  - `aria-label` on the theme toggle button (no visible text)
  - `aria-label` on edit/delete buttons in `history.html` including the entry date
  - `<label>` for every form field confirmed across all templates
- CSS polish: adjusted spacing, font sizes, and card padding for mobile; verified all three themes pass colour contrast requirements using Chrome DevTools accessibility checker.

**Why I did it:**
- The `{% endblock %}` bug caused Jinja2 to render `</div>` tags outside the block scope, which produced structurally invalid HTML the page appeared to render but failed W3C validation and broke layout inheritance.
- `role="main"` and other landmark roles allow screen reader users to jump directly to the main content area without tabbing through the entire navbar particularly important for users with motor impairments.
- `aria-label` on the theme toggle button is required because the button contains only an icon character (☾/☀/♥) without a text label or aria-label, a screen reader announces the raw Unicode character rather than a meaningful description.

**Challenges:**
- Colour contrast in the purple theme was initially insufficient for body text  Chrome Lighthouse flagged it. Adjusted `--text-color` from `#d0b0ff` to `#f0e6ff` to achieve the required 4.5:1 contrast ratio for normal text.
- The skip link must be the first focusable element in the DOM (before the navbar) to be useful initially placed it after the `<nav>` tag, which meant keyboard users still had to tab through the entire navigation first.
